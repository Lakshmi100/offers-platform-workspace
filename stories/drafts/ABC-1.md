# ABC-1: Core-banking Postgres database in the ABC Bank account

**Repo:** `abc-bank` · **Milestone:** Phase 2: ABC Bank source · **Estimate:** 5 pts
**Labels:** `story`, `needs-approval`, `infra`, `finops`, `abc-bank`, `dea-domain-2`
**Approver:** Lakshmi100 · **Status:** draft round 3, not yet an issue

## User story

**As** the ABC Bank data owner,
**I want** a Postgres database for core banking in the ABC Bank AWS account, built from code,
**so that** the bank's customer and transaction data has a home that the Offers Platform can later receive changes from through DMS.

## Context

The roadmap's source-system decision is "ABC Bank core banking on RDS Postgres;
change data capture with DMS" (`docs/00-roadmap.md` §1 and Phase 2 in §4).
This is the first Phase 2 story; ABC-2 to ABC-5 (tables, generator, data load)
build on it. The database is a development environment for a portfolio build,
not production, so it exists only during working sessions.

## Requirements

1. A managed PostgreSQL database (Amazon RDS) exists in the ABC Bank account, in `us-east-1`, defined in Terraform in its own **session root** under `infra/` (see "Terraform roots" in `AGENTS.md`).
2. It contains an empty database named `core_banking`.
3. It is ready for DMS change data capture (inserts, updates and deletes) from the start, so that adding CDC later does not require rebuilding it.
4. The engineer connects with `psql` from their laptop, signed in with their **Identity Center engineering role** and **IAM database authentication** (a short-lived token; no password to handle). The database is never reachable from the internet.
5. One command creates everything this story needs, and one command removes it, without touching the long-lived foundations (FND-2, FND-3, FND-4).
6. It is sized for development and for loading scale factor 10 (about 10,000 customers and 16 million transactions, a few GB), not for production load. ABC-5's SF10 load is the test of this size; if that load fails for lack of capacity, resizing is a change to this story's root.
7. The admin password is generated by AWS and stored in Secrets Manager, encrypted with the ABC Bank KMS key. It is for administration only. It never appears in the repo, Terraform state, Terraform outputs, or plan output.

## Constraints

| Area | Constraint |
|---|---|
| Personal data | No data in this story. From ABC-2 on the database holds (synthetic) personal data, so encryption and access rules apply from creation. |
| Card data (PCI) | Not applicable: no tables or data in this story. |
| Network and access | No public endpoint, no internet gateway, no NAT gateway. People get in only through Identity Center roles; no IAM users, access keys or EC2 key pairs. |
| Encryption | The database's storage and backups, its secret in Secrets Manager, and any logs it exports are encrypted with the ABC Bank customer-managed KMS key (FND-3). |
| Cost | Session resources: created per working session and destroyed after it. A 3-hour session, including the access path, costs under $1. |
| Tagging | Every resource carries the four cost tags with the values in `AGENTS.md`. |
| Downstream compatibility | Meets AWS DMS's prerequisites for a PostgreSQL CDC source (supported engine version, logical replication). |

## Acceptance criteria

Every criterion runs against the real ABC Bank account, as `AGENTS.md` allows for stories that say so.

- [ ] **AC1** In an ABC Bank account with FND-1 to FND-4 done, `terraform apply` in ABC-1's session root completes without errors.
- [ ] **AC2** With the Identity Center engineering role's CLI profile, the engineer generates an IAM authentication token and connects with `psql` to `core_banking` from their laptop; `select version();` returns a PostgreSQL version that AWS DMS supports as a CDC source.
- [ ] **AC3** `SHOW wal_level;` returns `logical`.
- [ ] **AC4** `aws rds describe-db-instances` shows `PubliclyAccessible: false` and `IAMDatabaseAuthenticationEnabled: true`, and no security group attached to the database allows inbound traffic from `0.0.0.0/0` or `::/0`.
- [ ] **AC5** The database's storage, its Secrets Manager secret, and any CloudWatch log group it exports to use the ABC Bank customer-managed KMS key, not an AWS-managed key.
- [ ] **AC6** Searching the repo, the Terraform state file, `terraform output`, and the saved plan output for the admin password finds nothing.
- [ ] **AC7** Every resource the story creates has the four cost tags with the values in `AGENTS.md` (checked with the Resource Groups Tagging API).
- [ ] **AC8** After `terraform destroy`, the Resource Groups Tagging API and `aws rds describe-db-snapshots` find no resource left from this story, and the FND-2, FND-3 and FND-4 resources are unchanged.
- [ ] **AC9** While the session runs: `aws iam list-users` returns none, no EC2 key pair exists, and no NAT gateway or internet gateway exists in the ABC Bank account.
- [ ] **AC10** The PR records the session's cost (from Cost Explorer by tag; if tag data isn't available yet, an estimate from the AWS pricing of each resource for the hours it ran) and it is under $1.
- [ ] **AC11** `terraform fmt -check` and `terraform validate` pass.

## Out of scope

- Tables and schema (ABC-2, ABC-3); the data generator and data loading (ABC-4, ABC-5)
- Database users and roles beyond what IAM authentication for the engineer needs (ABC-2 decides the schema owner)
- DMS endpoints and tasks (a later Phase 2 story)
- High availability (Multi-AZ), read replicas, backup tuning, production sizing
- Deploying from GitHub Actions
- The long-lived foundations themselves (FND-1 to FND-5)

## Depends on

- FND-1: the ABC Bank account, and the Identity Center engineering role with `rds-db:connect` and Cost Explorer read access.
- FND-2: Terraform state storage for the ABC Bank account.
- FND-3: the ABC Bank customer-managed KMS key (looked up by alias).
- FND-4: the private network (VPC and private subnets, looked up by name or tag).
- FND-5: cost-allocation tags activated, so AC10 can read the session's cost by tag.

## Decisions

- Nov 1, 2026: the engineer connects with IAM database authentication through the Identity Center engineering role.
- Nov 1, 2026: `abc-bank` uses separate Terraform roots for long-lived foundations and per-session resources (`AGENTS.md`, "Terraform roots").
- To confirm (from round 1 of this draft): no internet reachability at all, and the $1-per-3-hour session limit.
